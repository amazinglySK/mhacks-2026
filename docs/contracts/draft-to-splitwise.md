# Draft-to-Splitwise Operation Contract

**Resolution for:** [Issue #9](https://github.com/amazinglySK/mhacks-2026/issues/9)  
**Date:** 2026-10-03

This document defines the structured operation contract between the Reasoning Agent's interpretation layer and its Splitwise API client for the three MVP operations: create expense, correct expense, and balance readback.

---

## Draft Schema

Drafts are stored in Agentverse Agent Storage during a Listening Session. Each draft represents a parsed expense ready to commit to Splitwise.

### TypeScript Interface

```typescript
interface Draft {
  id: string;  // UUID, generated by agent
  status: 'draft' | 'committed';
  
  // Core expense data
  amount: string;  // "25.00" - matches Splitwise string format
  description: string;  // "Pizza party"
  currency_code: string;  // "USD" - defaults to group's currency
  
  // Participants with shares
  shares: Array<{
    user_id: number;  // Splitwise user ID
    paid_share: string;  // "25.00" or "0.00"
    owed_share: string;  // "12.50"
  }>;
  
  // Optional fields
  details?: string;  // Additional notes
  date?: string;  // ISO 8601, defaults to now
  
  // Audit trail
  source_messages: Array<{
    id: string;  // iMessage message ID
    sender: string;  // iMessage handle
  }>;
  created_at: string;  // ISO 8601
  updated_at: string;  // ISO 8601
  
  // Post-commit reference
  splitwise_expense_id?: number;  // Set after successful commit
  committed_at?: string;  // ISO 8601
}
```

### Storage Key Pattern

`session_{group_chat_id}_draft_{draft_id}`

## Design Decisions

### 1. Computed Shares Only

**Decision:** Store final `owed_share` values directly, not the split rule type.

**Rationale:** 
- Agent computes equal splits immediately (including exclusions)
- No need to remember "equal" vs "custom" after creation
- Splitwise "by shares" mode requires computed shares anyway
- Simplifies modification logic (just recompute and replace)

### 2. Unified Share Structure (Paid + Owed)

**Decision:** Each participant has both `paid_share` and `owed_share`. Payer(s) have `paid_share > 0`.

**Rationale:**
- Matches Splitwise "by shares" API exactly
- Supports multi-payer scenarios without schema changes (e.g., "Alice paid $20, Bob paid $10")
- Single array instead of separate payer/participants fields

### 3. Agent Computes and Rounds Shares

**Decision:** Agent divides amount by participant count and rounds to 2 decimals using standard rounding (0.5 rounds up).

**Rationale:**
- Can't use Splitwise `split_equally=true` mode (doesn't support exclusions)
- Splitwise API requires 2 decimal places
- Deterministic rounding prevents surprises

**Edge case handling:** If shares don't sum to `cost` due to rounding (e.g., $10 ÷ 3 = $3.33 × 3 = $9.99), adjust the payer's `owed_share` by the remainder to balance.

### 4. Source Messages: IDs + Sender Only

**Decision:** Store `{id, sender}` per source message, not full text.

**Rationale:**
- Audit trail for debugging ("which user triggered this?")
- Enables potential "undo" UX later
- Avoids privacy and storage concerns of full message text

### 5. Post-Commit Reference in Draft

**Decision:** Add `splitwise_expense_id` field to Draft on commit success. Keep committed drafts in storage.

**Rationale:**
- Enables corrections: fuzzy-match description → lookup expense ID
- No separate corrections_map data structure
- Audit trail of session history
- Prune old sessions after N days (not blocking for MVP)

## Operation Mappings

### 1. Create Expense: Draft → Splitwise API

**API Call:** `POST /create_expense`

**Mapping Function:**

```python
def draft_to_create_expense_payload(draft: Draft, group_id: int) -> dict:
    payload = {
        "group_id": group_id,
        "cost": draft.amount,
        "description": draft.description,
        "currency_code": draft.currency_code,
    }
    
    # Add optional fields if present
    if draft.details:
        payload["details"] = draft.details
    if draft.date:
        payload["date"] = draft.date
    
    # Add shares (flattened format)
    for i, share in enumerate(draft.shares):
        payload[f"users__{i}__user_id"] = share.user_id
        payload[f"users__{i}__paid_share"] = share.paid_share
        payload[f"users__{i}__owed_share"] = share.owed_share
    
    return payload
```

**Pre-commit Validation:**

```python
def validate_draft(draft: Draft) -> list[str]:
    """Returns list of error messages, empty if valid."""
    errors = []
    
    # Sum checks
    total_paid = sum(Decimal(s.paid_share) for s in draft.shares)
    total_owed = sum(Decimal(s.owed_share) for s in draft.shares)
    cost = Decimal(draft.amount)
    
    if total_paid != cost:
        errors.append(f"paid_share sum {total_paid} != cost {cost}")
    if total_owed != cost:
        errors.append(f"owed_share sum {total_owed} != cost {cost}")
    
    # No negative shares
    for s in draft.shares:
        if Decimal(s.paid_share) < 0 or Decimal(s.owed_share) < 0:
            errors.append(f"Negative share for user {s.user_id}")
    
    return errors
```

**Validation Rules:**
- ✅ Sum of `paid_share` must equal `cost`
- ✅ Sum of `owed_share` must equal `cost`
- ✅ No negative `paid_share` or `owed_share`
- ✅ Valid `currency_code` (assumed validated during draft creation)
- ❌ Don't require all participants have `owed_share > 0` (Splitwise allows zero, useful for "paid but not splitting")
- ❌ Don't require payer has `paid_share > 0` globally (multi-payer edge cases)

**Response Handling:**

```python
response = await splitwise_api.create_expense(payload)

# CRITICAL: API returns 200 OK even on failure
if response.get("errors") and len(response["errors"]) > 0:
    error_msg = "; ".join(response["errors"].get("base", ["Unknown error"]))
    raise SplitwiseAPIError(error_msg)

# Success
expense_id = response["expenses"][0]["id"]
draft.status = "committed"
draft.splitwise_expense_id = expense_id
draft.committed_at = datetime.now(timezone.utc).isoformat()
await storage.save(draft)
```

### 2. Correct Expense: Modification → Splitwise API

**API Call:** `POST /update_expense/{id}`

**Process Flow:**

1. **User says:** "change the pizza to $35" (in-session or explicit `@agent correct` command)
2. **Agent finds draft:** Fuzzy-match description against committed drafts → gets `splitwise_expense_id`
3. **Agent asks for clarification:** "What should I update? Amount, participants, or split?"
4. **Agent recomputes shares:** If amount changes, recompute all `owed_share` values proportionally
5. **Agent calls update:** Must include **complete** new share list (Splitwise overwrites all shares)

**Mapping Function:**

```python
def correction_to_update_payload(
    original_draft: Draft,
    new_amount: str = None,
    new_shares: list = None,
    new_description: str = None
) -> dict:
    payload = {}
    
    # Update description if provided
    if new_description:
        payload["description"] = new_description
    
    # Recompute shares proportionally if amount changes
    if new_amount:
        payload["cost"] = new_amount
        old_cost = Decimal(original_draft.amount)
        new_cost = Decimal(new_amount)
        ratio = new_cost / old_cost
        
        new_shares = [
            {
                "user_id": s.user_id,
                "paid_share": str((Decimal(s.paid_share) * ratio).quantize(Decimal("0.01"))),
                "owed_share": str((Decimal(s.owed_share) * ratio).quantize(Decimal("0.01")))
            }
            for s in original_draft.shares
        ]
    
    # CRITICAL: Must include ALL shares (Splitwise overwrites)
    shares_to_send = new_shares or original_draft.shares
    for i, share in enumerate(shares_to_send):
        payload[f"users__{i}__user_id"] = share.user_id
        payload[f"users__{i}__paid_share"] = share.paid_share
        payload[f"users__{i}__owed_share"] = share.owed_share
    
    return payload
```

**Critical Note:** Splitwise `update_expense` **replaces** all shares if any `users__N__*` parameter is provided. Always send the complete participant list, not partial updates.

**Context-Dependent Invocation:**
- **Inside session:** Natural language modification ("change that to $35") triggers immediate update
- **Outside session:** Explicit command (`@agent correct pizza to $35`) required

### 3. Balance Readback: Query → Natural Language Summary

**API Call:** `GET /get_group/{id}`

**Process Flow:**

1. Call Splitwise `GET /get_group/{group_id}`
2. Parse `group.members[].balance` (individual balances)
3. Parse `group.simplified_debts` (who pays whom)
4. Format as natural language summary

**Mapping Function:**

```python
def format_balance_summary(group_response: dict) -> str:
    lines = ["💰 Current balances:\n"]
    
    # Individual balances
    for member in group_response["members"]:
        if member["balance"]:
            bal = member["balance"][0]  # Assume single currency for MVP
            amount = Decimal(bal["amount"])
            if amount < 0:
                lines.append(f"  {member['first_name']} owes {abs(amount):.2f} {bal['currency_code']}")
            elif amount > 0:
                lines.append(f"  {member['first_name']} is owed {amount:.2f} {bal['currency_code']}")
            else:
                lines.append(f"  {member['first_name']} is settled up")
    
    # Simplified debts (payment instructions)
    if group_response["simplified_debts"]:
        lines.append("\n📤 Suggested payments:")
        for debt in group_response["simplified_debts"]:
            from_name = next(m["first_name"] for m in group_response["members"] if m["id"] == debt["from"])
            to_name = next(m["first_name"] for m in group_response["members"] if m["id"] == debt["to"])
            lines.append(f"  {from_name} → {to_name}: {debt['amount']} {debt['currency_code']}")
    
    return "\n".join(lines)
```

**Example Output:**

```
💰 Current balances:

  Alice owes 15.50 USD
  Bob is owed 10.00 USD
  Charlie is settled up

📤 Suggested payments:
  Alice → Bob: 15.50 USD
```

**No state storage needed** — this is a read-only query.

## Batch Commit Process

When the listening session stops and user confirms the final Photon app card, all drafts commit in a **best-effort batch**.

### Process

```python
async def commit_drafts_and_notify(session: ListeningSession) -> str:
    results = {"succeeded": [], "failed": []}
    
    for draft in session.drafts:
        if draft.status != 'draft':
            continue  # Skip already committed
        
        try:
            # Validate
            errors = validate_draft(draft)
            if errors:
                results["failed"].append({
                    "draft": draft,
                    "error": "; ".join(errors)
                })
                continue
            
            # Create expense
            payload = draft_to_create_expense_payload(draft, session.group_id)
            response = await splitwise_api.create_expense(payload)
            
            # Check for API errors (200 OK with errors field)
            if response.get("errors") and len(response["errors"]) > 0:
                error_msg = "; ".join(response["errors"].get("base", ["Unknown error"]))
                results["failed"].append({
                    "draft": draft,
                    "error": error_msg
                })
                continue
            
            # Success - update draft
            expense_id = response["expenses"][0]["id"]
            draft.status = "committed"
            draft.splitwise_expense_id = expense_id
            draft.committed_at = datetime.now(timezone.utc).isoformat()
            await storage.save(draft)
            
            results["succeeded"].append({
                "draft": draft,
                "expense_id": expense_id
            })
            
        except Exception as e:
            results["failed"].append({
                "draft": draft,
                "error": str(e)
            })
    
    # Format natural language response
    success_count = len(results["succeeded"])
    fail_count = len(results["failed"])
    
    if success_count > 0 and fail_count == 0:
        return f"✅ Done! {success_count} expense{'s' if success_count != 1 else ''} recorded. Check Splitwise to see the updates."
    
    elif success_count > 0 and fail_count > 0:
        failed_descriptions = [item["draft"].description for item in results["failed"]]
        return f"✅ Recorded {success_count} expense{'s' if success_count != 1 else ''}.\n\n❌ Couldn't record {fail_count}: {', '.join(failed_descriptions)}. Want me to try again?"
    
    else:  # All failed
        return f"❌ Couldn't record any expenses (Splitwise API issue). Want to retry, or should I save these drafts for later?"
```

### User Messaging Examples

**All success:**
```
✅ Done! 3 expenses recorded. Check Splitwise to see the updates.
```

**Partial success:**
```
✅ Recorded 2 expenses.

❌ Couldn't record 1: Pizza party. Want me to try again?
```

**All failed:**
```
❌ Couldn't record any expenses (Splitwise API issue). Want to retry, or should I save these drafts for later?
```

### Behavior

- **Best-effort:** Continue attempting remaining drafts even if one fails
- **Natural language:** Conversational tone, not robotic status codes
- **Deferred verification:** Tell user to check Splitwise later, don't show all IDs inline
- **Retry prompt:** On failure, ask if user wants to retry
